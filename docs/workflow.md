# 开发、测试、反馈流程

> 2026-10-17 和用户一起定下。所有会话和子任务都照这份做；流程改了就改这份，并在末尾的变更记录里记一笔。

## 一、分工

| 角色 | 谁 | 管什么 |
|---|---|---|
| 用户 | 你 | 提需求；定功能放在哪、怎么用；验收真机效果；决定发不发版、版本号 |
| 协调 | 主会话 | 拆任务、写方案、派子任务、合并、汇报 |
| 外观评审 | 任何会话或子任务 | 读 `docs/design/style.md` 和 `docs/design/specs/`，出外观方案、审图。不绑定某个固定会话 |
| 开发 | 子任务 | 在自己的工作区（`../pet-<主题>`）和分支上开发、写测试、按测试级别去测 |

## 二、每一项工作的循环

1. **收集**：需求、问题都记成 GitHub issue，以 issue 为准。
2. **方案**：凡是你会看到、会点到的，必须先有方案，**你确认了才动手**。方案写清楚：
   - 放在哪个界面；
   - 怎么进去，一步一步写；
   - 为什么放这里，还有哪些备选；
   - 附样例：只改外观的，给样例页截图；新交互，给能点的小原型。

   不改界面的修复，写清原因和修法就开工。
3. **外观**：涉及外观的，按 `docs/design/style.md` 来；拿不准的，外观评审先出一轮本机预览。
4. **开发**：
   - 先同步到最新主线，在自己的分支上做；
   - 带单元测试；
   - 不直接改主线，不碰你电脑上正在跑的宠物。
5. **测试**：按第三节的级别，只测和改动相关的。
6. **你验收**：
   - 改了外观的，看改前改后对比图；
   - 改了交互的，在试玩页（分支版）里亲手试；
   - 小修复在测试通过后直接合并，事后告诉你。
7. **合并**：合进主线，用登录任务把你电脑上的宠物换成新版，回复并关闭 issue。
8. **反馈**：你用了以后的意见，记成新的 issue，回到第 1 步。
9. **发版**（攒一批再发）：
   - 和上一版做空闲性能对比，不能更差；
   - 你定版本号；
   - 发布到 GitHub；
   - 在虚拟机里用上一版实测自动更新；
   - 推送 Gitee。Gitee 发布包要用你的 token 上传，所以由你来传。

   具体步骤见记忆里的发版流程。

### 需要你定的事
- 攒成一批，每项附样例，一次问完。
- 你不在时（无人值守）：先做在分支上，不合进主线，等你回来一起定。不替你做主后直接发布。

## 三、测试分级

| 级别 | 什么时候做 | 做什么 | 大约耗时 |
|---|---|---|---|
| L0 | 每个改动 | `node --test test/*.test.js`（必须这样写，单写 `node --test` 会卡住）、`cargo test`、`cargo build --release`，看程序体积 | 5 分钟 |
| L1 | 改了外观 | `pwsh tools/preview/render.ps1 -Out <文件夹> [-Only 场景名]`，出改前改后对比图 | 几分钟 |
| L2 | 改了鼠标、窗口、任务栏这类行为 | 先在试玩页里试；再在无登录的虚拟机里只跑相关的那组真鼠标测试 | 10～20 分钟 |
| L3 | 改了 agent 接入或钩子 | 只在有登录的 WakuTest 里测受影响的那个 agent，用最便宜的模型 | 10～30 分钟 |
| L4 | 改了常驻的东西：定时器、动画、轮询、新窗口 | 空闲性能对比（按处理器周期计，60 秒，每种情况两次以上） | 30～40 分钟 |
| L5 | 改了启动、开机自启、更新 | 反复重启（WakuTest2），或自动更新实测 | 30～60 分钟 |
| 发版前 | 每次发版 | 冒烟测试、L4、自动更新实测 | 约 2 小时 |

### 改了哪里，做哪几级（起步版，用着再补）
| 改动位置 | 级别 |
|---|---|
| 只改样式（`src/pet/*.css`）、小工具卡片的画法 | L0 + L1 |
| `island.js`、`settings.js`、`desk.js`、`bar.js` 的行为 | L0 + L1 + L2 |
| `pointer.rs`、`bridge.js`、`hovers.js`、`island.rs`（点击穿透、悬停） | L0 + L2，跑悬停、点击、菜单、编辑模式那一整组 |
| `events*.rs`、`connection.rs`、`server.rs`、`integrations/` | L0 + L3 |
| 定时、动画、轮询、新窗口（`hw.rs`、`desk.rs`、`widgets.rs`、`taskbar.rs` 的循环、`power.rs`） | L0 + L4 |
| 启动、`logon.rs`、开机自启、`updates.rs` | L0 + L5 |

**交代子任务时，在任务说明里写明要做哪几级。** 不默认全测；外观图只在最后验收时拍一次。

## 四、工具

| 工具 | 在哪 | 用来 |
|---|---|---|
| 样例页 | `tools/preview/render.ps1` | 用真页面渲染所有界面的截图，深浅色各一套；L1 对比、外观审图 |
| 试玩页 | `tools/preview/playground.html`；`node tools/preview/publish.js build <文件夹>` 打包，发布成 Artifact | 亲手试手感。主线版一个固定链接；分支要验收时，另发一份分支版 |
| 虚拟机 | `D:\VM\WakuTest\vm.ps1`；用 `Use-WakuVM <名字>` 选机器 | L2～L5 |
| 设计文档 | `docs/design/` | 风格和语言（`style.md`），功能规格的快照（`specs/`） |

### 虚拟机
| 名字 | 登录状态 | 用来 |
|---|---|---|
| WakuTest | 有你的各个 agent 账号 | 只测 agent（L3），一次只跑一个任务 |
| WakuTest2 | 无登录 | 开机自启、反复重启（L5） |
| WakuTest3、WakuTest4 | 无登录 | 界面、行为、性能（L2、L4），可以并行 |

这台电脑是常开的家庭服务器，虚拟机可以一直开着，不够再加。
